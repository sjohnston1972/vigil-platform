# VIGIL UI Design Spec

**Date:** 2026-03-18
**Status:** Approved
**Scope:** Visual design for all four sections of the VIGIL React UI (services/ui)

---

## 1. Overview

The VIGIL UI is a professional operations tool for managed network services. It is built with React + Vite and runs in `services/ui`. The design prioritises information density, clarity under pressure, and an aesthetic that reads as a serious security/ops tool — not a consumer app.

---

## 2. Global Shell

### Layout
- **Wide left sidebar** — fixed, always visible, ~200px wide
- **Main content area** — fills remaining viewport width
- No top navigation bar

### Left Sidebar Structure
```

─────────────────────────
⊞  Dashboard                  ← active item has indigo left border + subtle highlight
💬 Chat
```

## 3. Dashboard

The landing page. Shown on first load and when the user clicks Dashboard in the sidebar.

### Layout (top to bottom)
1. **4 stat tiles** — single row across the top of the content area
2. **Attention banner** — amber, appears only when there are pending approvals or failures; hidden otherwise
3. **Recent Activity feed** — scrollable list of recent agent actions

### Stat Tiles
Four equal-width tiles in a row:
- **Active Sessions** — green value
- **Pending Approvals** — amber value; tile border glows amber when > 0
- **Failures** — red value
- **Tokens Today** — indigo value

Each tile: card background, border, value in large coloured numeral, label in muted small caps below.

### Attention Banner
Amber background (`#1a1200`), amber border, amber text. Right side has a "Review →" button (amber filled, black text). Only rendered when `pendingApprovals > 0 || failures > 0`.

### Activity Feed
Labelled "Recent Activity" in indigo small-caps. Each row:
- Icon (✅ ⏳ 📋 🔍 etc.)
- Description text
- Relative timestamp (muted, right-aligned)

Step-up events render with amber text.

## 4. Chat View

### Layout (left to right)
1. **Session list panel** (~160px) — list of past conversations for this tenant
2. **Chat area** — fills remaining width
3. **Agent panel** — collapsible, right edge

### Session List
- Header: "Sessions" in indigo small-caps
- Active session: indigo left border, slightly highlighted background
- Each entry:
  - **Title**: auto-generated by the coordinator on first save (short summary, e.g. "BGP audit — router-core-01"). Falls back to first user message truncated if no title yet.
  - **Agent badges**: small coloured dots or abbreviated agent names below the title (e.g. `net` `rag` `enrich`) indicating which specialist agents were involved
  - **Rename**: double-click the title to edit it inline; saves on blur/Enter
- "＋ New chat" button at bottom, dashed border

### Chat Area
- User messages: right-aligned, card background, slate body text
- Assistant messages: left-aligned, `#1e1b4b` background, `#c7d2fe` text
- Tokens stream in character by character during live responses
- Input box pinned to bottom: dark background, border, muted placeholder

### Agent Panel (collapsible)
**Collapsed state** (default):
- Slim strip (~28px) on the right edge
- "AGENTS" label rotated 90°
- Coloured dots (green = complete, amber = running, red = error) stacked vertically
- `›` expand button at bottom

**Expanded state** (~140px):
- "AGENTS" header in indigo small-caps
- Per-message groups, collapsible:
  - `▾ Message N` — expanded group shows each agent row
  - Each row: coloured dot, agent name, duration in muted text
- Token count at bottom, muted

Agent dot colours: amber while running, green on complete, red on error.

### Step-Up Approval Banner
When a step-up approval is required, a sticky banner appears spanning the full content area (all three columns: session list, chat area, and agent panel — everything to the right of the global sidebar):
- Full width, amber background (`#1a1200`), amber border bottom
- Left: `⚠ [tool_name] needs approval — [device] · expires [MM:SS]`
- Right: green "Approve" button + red "Reject" button (small, inline)
- Chat area beneath is dimmed (`opacity: 0.5`) while banner is active
- Banner disappears once approved, rejected, or expired

## 5. Audit Logs

### Layout
- Filter bar at top: search input + Agent dropdown + Date range dropdown
- Table below, fills remaining height, scrollable

### Table
Columns: **Time** | **Agent** | **Action** | **Tokens**

- **Time**: HH:MM:SS timestamp
- **Agent**: agent name (e.g. `network_agent`, `itsm_agent`, `step-up`)
- **Action**: free-text description from the audit log entry (e.g. "BGP audit — 10.0.0.1", "Ticket #4421 created", "apply_change approved — router-core-01")
- **Tokens**: integer token count, or `—` for non-LLM events (step-up approvals, etc.)

Each row:
- Background: card colour, border
- Agent name coloured by type (all use indigo-400 by default; step-up events use amber)
- Step-up rows: amber background (`#2d1f00`), amber border, amber text
- Expand chevron (`›`) on right edge of each row

**Expanded row** (click to toggle):
- Drops down a detail strip below the row, dark background
- Shows: Session ID (indigo link), Agents involved (comma list), Duration
- Row border changes to indigo when expanded

## 6. Admin

### Navigation
Sub-pages are nested under Admin in the left sidebar when Admin is active:
- **Tenants** — default sub-page
- **Token Budgets**
- **Agent Health**

Active sub-page has the same indigo left-border treatment as top-level nav items.

### Tenants Sub-page
Table of tenants:
- Columns: **Tenant** | **Status** | **Budget Used** | **Edit**
- Active tenants: green dot + "Active"
- Suspended tenants: red dot + "Suspended", row text muted
- "Edit" is an indigo text link

### Token Budgets Sub-page
Per-tenant budget configuration:
- Columns: **Tenant** | **Daily Limit** | **Used Today** | **Reset** | **Edit**
- Usage shown as `42k / 100k` — colour shifts amber when > 80%, red when > 95%

### Agent Health Sub-page
Per-agent status grid:
- Agent name, last heartbeat, status (green/amber/red), response time (p95)
- Stale agents (no heartbeat > 60s) highlighted amber

## 9. SSE Integration Notes

The chat view consumes the SSE stream from the Gateway (`POST /chat/stream`). Event handling:

| SSE Event | UI action |
|---|---|
| `session_start` | Open session entry in SessionList |
| `agent_start` | Add agent row to AgentPanel with amber dot |
| `agent_complete` | Update row: green dot + duration |
| `agent_error` | Update row: red dot + error text |
| `token` | Append character to current MessageBubble |
| `approval_required` | Show StepUpBanner, dim chat |
| `approval_granted` | Dismiss StepUpBanner, resume stream |
| `approval_rejected` | Dismiss banner, show rejection message in chat |
| `approval_expired` | Dismiss banner, show timeout message in chat |
| `done` | Finalise message, update token counter in AgentPanel |
| `error` | Show error state in MessageBubble |

The `useStream` hook (per `CLAUDE.md` SSE pattern) drives all of this — `fetch` + `ReadableStream`, never `EventSource`.

The approval-related events (`approval_required`, `approval_granted`, `approval_rejected`, `approval_expired`) are already defined and emitted by the coordinator — see `services/coordinator/step_up.py` and `docs/superpowers/specs/2026-03-17-step-up-auth-design.md`. No backend changes are required to implement the step-up banner.
